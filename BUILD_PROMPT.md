# One-shot prompt: build the dashboard from scratch

Paste the prompt below into a coding assistant that can create local files and run a web server. For the exact existing implementation, use [the setup prompt](ONE_SHOT_PROMPT.md).

```text
Build me a complete local dashboard called Jev Inbox to organize my Gmail emails and YouTube comments using the Jev decision model through OpenRouter. Make it minimalist, professional, easy to read, and familiar to a Gmail user: pale blue and white, a left mailbox and label sidebar, a large search bar, dense email rows, source tabs, category and sort filters, and a focused reading-and-reply view. Use locally served Google Material Symbols and Roboto with their licenses, plus Gmail and YouTube logos only to identify their integrations. It must work on desktop and narrow mobile screens.

Keep it local at http://localhost:5184 and bind only to 127.0.0.1. Do not use a site builder, deploy it, or create a public tunnel. Use a simple modern Node.js backend, SQLite storage, and a lightweight browser frontend. Include Mac, Windows, and Linux launchers, a Node version check, clear startup errors, and an easy README. Prefer no npm runtime dependencies. Begin with explicitly fictional sample messages and a separate empty live inbox. Never invent real connections, AI results, or timings.

Add a first-run checklist and Settings for Google setup, Gmail sign-in, OpenRouter, workflow, and reply templates. Each person must use their own Google Cloud project, OAuth web application client, Gmail account, and OpenRouter key. Include exact instructions for enabling Gmail API, configuring the consent screen and test users, creating the OAuth client, and registering http://localhost:5184/auth/google/callback. YouTube should be optional. Google login must use OAuth state and PKCE; passwords remain with Google. Store keys and tokens encrypted server-side with a local encryption key, keep data files private, and return only masked key hints to the frontend. Do not put secrets in source, URLs, logs, prompts, screenshots, or releases. Protect local mutations with sessions, same-origin checks, and CSRF tokens.

Use Jev through the OpenRouter Decisions API, defaulting to typesafe/jev-1.14, with configurable model and API key plus a connection test. Ask structured questions for category, priority, whether a reply is needed, a suitable saved template, and sensitive content. Jev is a decision model, not a free-form reply generator. Use these 17 primary categories with clear intent-based definitions: Partnerships, Collaborations, Sponsorships, Press & interviews, Events & speaking, Customer support, Billing & payments, Questions, Feedback, Appreciation, Newsletters, Promotions, Notifications, Security, Other business, Spam, and Other. Distinguish paid brand campaigns from ongoing partnerships and creator collaborations; keep legitimate marketing out of Spam, receipts in Billing, and login alerts in Security. Show category confidence separately from other decisions, explain review reasons, and make manual category corrections persist. Low-confidence and sensitive messages require review. Never promise perfect AI accuracy.

Offer batch sizes 50, 100, 250, 500, and 1,000. Scan newest matching individual Gmail emails, with Last 30 days, Last 90 days, All Inbox mail, and custom Gmail search. Fetch all needed pages; normalize plain-text and HTML-only bodies safely without executing HTML or loading remote images. Reuse complete saved email bodies, automatically refresh outdated classification rules, and distinguish unclassified messages as Unsorted. Implement Scan & run Jev and a separate Recheck saved labels action that uses local messages without another Gmail download. Use a bounded worker queue, shared backoff for OpenRouter rate limits, Google quota-aware pacing, and stop the queue on persistent permission or quota errors. Preserve partial results and drafts. Verify current official provider quotas rather than assuming old limits.

Show a prominent live total-run timer, separate Gmail and Jev timings, counts for scanned, successfully classified, reused, newly downloaded, and failed messages, and a visible blue Time (sec) column beside Sender for each model request. Persist run history, batch size and source, date range, completion status, and errors. Stop run should finish current requests and preserve completed work. Optional five-minute sync is off by default and runs only while the local server is open.

Support editable reply templates and personal drafts. Every real email or comment reply requires a preview with the exact recipient and text, then explicit confirmation. Preserve email threading, prevent duplicate sends, bind messages to the correct connected account, and treat uncertain delivery as requiring inspection rather than automatically retrying. Local labels and archive actions should stay local unless I separately request provider changes.

Test the real application code with mocked providers: OAuth and CSRF validation, Gmail pagination to 1,000, caching, HTML extraction, quota failures, bounded concurrency and shared retries, classification version upgrades, preserved corrections and drafts, timing/count accuracy, and duplicate-send protection. Check the first-run and mobile interfaces in a browser. Provide a clean shareable ZIP containing only code, docs, licensed assets, and fictional samples. Exclude data directories, databases, API keys, OAuth credentials, tokens, encryption keys, logs, private screenshots, and all existing user messages. Finish with the local URL, launch instructions, and any remaining account setup I need to complete personally.
```
